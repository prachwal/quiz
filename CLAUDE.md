# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"quiz" is an early-stage React 19 + TypeScript + Vite app (Ant Design, React Router, Redux Toolkit + RTK Query) deployed on Vercel, with an Express backend running as a single serverless function and a Postgres (Neon) database.

## Commands

- `npm run dev` — Vite dev server (frontend only; use `npm run dev:full` to run Vite plus the API on :8888)
- `npm run dev:full` — builds `api/index.mjs`, then serves the Express app on :8888 and proxies Vite (HMR) behind it (`scripts/dev-server.mjs`)
- `npm run build` — `tsc -b && vite build` (output in `dist/`)
- `npm run lint` — Oxlint (config in `.oxlintrc.json`; not ESLint)
- `npm run preview` — serve the production build
- **Local login bypass** (`server/devAuth.ts`, `src/features/auth/devAuth.ts`): `DEV_AUTH_TOKEN` in `.env.local` is accepted as a Bearer credential acting as `DEV_AUTH_USER_ID` with `DEV_AUTH_ROLES`, but only under `npm run dev:full` (`LOCAL_DEV=true`, no production `NODE_ENV`, no Vercel runtime markers); `VITE_DEV_AUTH_TOKEN` skips the Auth0 login in dev builds (stripped from production bundles). Details in `docs/mcp.md`.
- `npm run test:mcp` — full local MCP test (`scripts/mcp-local-e2e.sh/.ts`; refuses a non-localhost `DATABASE_URL` unless `MCP_E2E_ALLOW_REMOTE_DB=1`): starts `scripts/dev-server.mjs` (or reuses a running one) and exercises all 27 tools, permissions and the audit trail with the official MCP client; test rows use the `mcp-e2e` prefix and are removed.
- `npm test` — unit tests in `tests/*.test.ts` (node:test; esbuild bundles them into `.test-build/` because this Node build cannot run TypeScript). Only pure logic is tested (no DB, no browser); keep such logic in import-free modules so tests can load it.

## Architecture

- **Frontend**: `index.html` → `src/main.tsx` (Redux `Provider`) → `src/App.tsx` (antd v6 `ConfigProvider` + antd `App` + React Router). antd 6 supports React 19 natively, so no compatibility patch is needed. Routes: `/` (quiz list with difficulty filter/popularity sort + random irregular-verbs quiz generator; cards show the *current user's* attempts and best score, `myAttempts`/`myBestPercent` from `GET /api/quizzes`), `/learn` (courses), `/learn/:courseId`, `/learn/:courseId/lessons/:lessonId` (one verb per slide via `VerbSlide`, Cofnij/Dalej buttons + arrow keys, the last slide completes the lesson), `/verbs`, `/results`, `/quizzes/new`, `/quizzes/:id/edit`, `/quizzes/:id/play`, `/about`, `/settings`, 404 — pages in `src/pages/` under `src/components/AppLayout.tsx`; client routes rely on the SPA fallback in `vercel.json`. Quiz UI is in `src/features/quizzes/`: `QuizEditor` (antd Form + `Form.List`, with `OptionsEditor` adapting to question type), `QuizPlayer`, and `questionRenderers.tsx` (player input per question type; choice answers are `ChoiceTile`s in a CSS grid `.choice-grid` — 2 columns, so four options form a 2x2 table, 1 column on narrow screens).
- **Look & feel**: the antd theme lives in `src/app/brandTheme.ts` (indigo brand, 16px body, heading scale, light/dark surfaces; used by `App.tsx` and `PublicShell`). `src/app/themeVars.ts` exposes a few tokens as `--app-*` CSS variables on `.app-shell` for the rules in `src/styles/` (imported in cascade order by `src/index.css`: `base`, `shell`, `components`, `pages`, `phones`, `touch`, `misc`; nav pills, card shadows/hover lift, focus rings, reduced-motion). Pages start with `src/components/PageHeader.tsx` (eyebrow/back link, title, subtitle, meta, actions); the logo is `BrandMark`. Below `lg` the header nav collapses into a Drawer. **Mobile mode** (breakpoints documented at the top of `index.css`, JS twin in `src/app/useMediaQuery.ts` - `PHONE_QUERY` < 768px, `COARSE_QUERY`): nav visibility is pure CSS (pill nav >= 992px, hamburger 768-991px, `BottomNav` tab bar < 768px with "O aplikacji" as a link in the footer, which stays visible above the tab bar on phones and hides in focus mode; nav items in `navItems.tsx`), so avoid `Grid.useBreakpoint` for show/hide (it starts empty and flashes). On touch devices `brandTheme(dark, compact, touch)` raises control heights to 44px+. Quiz player and lesson slides call `useFocusMode()` (`src/components/useFocusMode.ts`): on phones the tab bar is hidden and their `.action-bar` becomes a fixed thumb-zone bar (safe-area aware); content padding is handled in CSS. Don't put a `transform` on ancestors of those fixed bars (the route fade is opacity-only on phones). Lesson slides support swipe (`useSwipe` + pure `swipe.ts`, `.swipe-area` = `touch-action: pan-y`). On phones, Results/Verbs/API tokens render the antd `Table` with a single card-like column (`.card-rows`, header hidden, simple pagination) and modals become bottom sheets (CSS). Safe areas use `env(safe-area-inset-*)` (`viewport-fit=cover`), heights `dvh` with `vh` fallback; `useDocumentTheme` syncs `theme-color`/`color-scheme`/`data-theme` with the chosen theme. `public/manifest.webmanifest` uses `display: minimal-ui` on purpose (iOS standalone mode breaks the Auth0 redirect login); no service worker. Prefer tokens (`theme.useToken()`) over hardcoded colors. antd injects a global `a { color: colorLink }` style, so custom link colors use `.app-shell a.<class>` selectors.
- **State**: `src/app/store.ts` combines the RTK Query `api` (`src/app/api.ts`, base URL `/api`; Quiz tags invalidate the list/detail caches) and the `settings` slice (`themeMode` light/dark/system, `compact`, `showExplanations`, `shuffleQuestions`). Settings are persisted to localStorage key `quiz:settings` by a store subscriber and preloaded/validated in `src/app/persist.ts` (synced across tabs). To add a persisted option, extend the slice, `defaultSettings` and `loadSettings`. `system` theme is resolved by `useResolvedTheme`.
- **Quiz player gotchas**: `QuizPlay` keys the player by quiz id and `QuizPlayer` reads `currentData` — navigating from a finished quiz to a freshly generated one reuses the same route component, so without that the old answers/result stayed on screen. "New quiz" buttons in `ResultView` clamp the question count to the generators' limits (`src/features/quizzes/counts.ts`, tested) and always surface errors.
- **Audio (text-to-speech)**: `src/features/audio/` — browser `speechSynthesis` (no audio files): `speech.ts` (module-level store for voices/active reading, pure `pickVoice`, `verbSpeechParts`), `useSpeech` (accent/rate from settings; `available` is false without an English voice, then `SpeakButton` renders nothing), `SpeakButton`. Used on lesson slides (base/forms/example, optional autoplay `autoSpeak`), the verbs table, quiz review of generated (English) quizzes and Settings → Wymowa (`speechAccent`, `speechRate`, `autoSpeak` in `settingsSlice`/`persist.ts`).
- **Progress (streak and daily goal)**: tables `user_profiles` (`daily_goal`, `timezone`) and `daily_activity` (per user/day: answered, correct, lessons). `grade` and a *first* lesson completion call `progress.recordActivity` (`server/progressRepo.ts`); days are counted in the user's IANA time zone, which the client keeps in sync (`useTimezoneSync`). A day counts towards the streak after ≥1 answered question or a completed lesson; the current streak survives until the day ends. Pure logic (day arithmetic, streaks, last 7 days) lives in `src/shared/quiz/streaks.ts` with tests in `tests/streaks.test.ts`. API: `GET /api/progress/summary`, `PATCH /api/progress/profile`. UI: `src/features/progress/` (`StreakChip` in the header, `DailyGoalCard` on Home/Results, `WeekStrip`, `ProgressLine` after a quiz), goal picker in Settings.
- **Spaced repetition**: Leitner boxes 0–6 (intervals 0/1/2/4/8/16/32 days; a wrong answer resets to box 0 and is due immediately) — pure logic in `src/shared/quiz/spaced.ts` (tests in `tests/spaced.test.ts`). `verb_reviews` holds per-user state (`box`, `due_at`, `attempts`, `correct`, `lapses`…). Questions now carry `questions.verb_id` (set by `buildVerbQuiz` through `verbId`), so grading any verb question — random quiz, exam, review — updates the review state (`reviewsRepo.applyResults`); completing a lesson enqueues its verbs (`enqueueLessonVerbs`). API: `GET /api/reviews/summary`, `POST /api/reviews/session` (generated quiz, `source: 'review'`, most overdue first; 409 when nothing is due). UI: `ReviewCard` on Home and Nauka, "Kolejna powtórka" in the result view.
- **Weak verbs / error training**: `verb_reviews` also tracks `last_wrong_at`. A verb is "weak" when it has ≥3 attempts, accuracy <75% and is not yet recovered (Leitner box <4) — pure ranking in `src/shared/quiz/weak.ts` (`tests/weak.test.ts`). API: `GET /api/progress/weak-verbs`, `POST /api/quizzes/generate/irregular-verbs` with `onlyWeak: true` (409 without data; tops up with random verbs when there are too few; `source: 'weak'`), `POST /api/quizzes/:id/retry-wrong` (new quiz from the verbs behind wrongly answered questions). UI: "Najtrudniejsze dla Ciebie" (`WeakVerbs`) on Results, "tylko moje słabe" switch in the Home generator, `WeakMark` tag on slides/verb list, "Powtórz błędne" and "Kolejny trening błędów" in the result view.
- **Classes (teacher)**: role `teacher` (Auth0, managed in the admin panel next to admin/student) with permission `manage:classes` (not granted to admin automatically; an admin who also needs it gets the teacher role). Tables `classes` (owner = teacher `sub`, 6-char `join_code`, soft-archive), `class_members`, `assignments` (course *or* manual quiz, optional due date). Students join with `POST /api/classes/join`; assignment status is derived from existing data (lesson progress + passed exam for courses, best attempt for quizzes — no extra bookkeeping). Teachers only ever see classes they own (others look like 404). Names/e-mails shown to teachers come from `user_profiles.display_name/email`, filled from the *verified access token* claims `https://quiz.local/name|email` (added by the "Quiz: roles claim" Action, v2) — never from client input; students are told on the join screen that the teacher sees their name, e-mail and results. Reports: `GET /api/classes/:id/report` (+ `.csv`, formula-injection safe — `src/shared/quiz/csv.ts`, tests in `tests/csv.test.ts`). UI: `/assignments` (everyone), `/classes`, `/classes/:id` (teacher; `RequireRole`), `AssignmentsHint` on Home. Teachers can rename a class, close/open joining (`classes.joining_open`; newcomers get 403, members are unaffected), change an assignment's due date and open a student's results (`GET /api/classes/:id/students/:userId` → `/classes/:id/students/:userId`, `StudentResults`): only attempts of the class's assigned quizzes/course exams, with per-question answers. Join codes are not rate limited yet.
- **API conventions**: handlers never answer `204`/`304` — a status that must not carry a body is fragile through serverless adapters and proxies. Mutations without data return `{ ok: true }`; ETags are disabled.
- **Quiz engine** (`src/shared/quiz/`, imported by both frontend and server): `engine.ts` holds the question-type registry (`questionTypes`: validate + grade + take the player view (`playerView`, no answers or correct order) + describe the answer for reviews (`describe`) per type — `single`, `multiple`, `truefalse`, `text`, `numeric`, `ordering`, `matching`, `cloze`) and `gradeQuiz`; `schema.ts` has the zod input schemas (type-specific rules run through the registry); `types.ts` the API shapes. To add a question type: add it to `QUESTION_TYPES` and `questionTypes` (a definition needs `usesOptions`, `defaultOptions`/`defaultConfig`, `validate`, `grade`, `playerView`, `describe`), a renderer in `questionRenderers.tsx` (a real component — renderers may use hooks, the player renders them as `<Renderer />`), a branch in `OptionsEditor` (options types) or `ConfigEditor` (config types, `usesOptions: false`; answers live in `questions.config` JSONB), a branch in `data/quiz.schema.json` and cases in `tests/engine.test.ts` + `tests/quizSchema.test.ts`. Grading is server-side only; the player view of a quiz (`GET /api/quizzes/:id`) omits `isCorrect`, explanations and the options of `text` questions — `?include=answers` returns the editor view. Types that need per-question state keep it in `config`: `numeric` (`{answer, tolerance?}`), `ordering` (`{items: [{id, text}]}` in the author order — `playerView` shuffles them with the injected `rng` and never returns the author order, so never shuffle such a payload on the client; the player submits `answer.order`, graded 0/1 on the normalized text sequence, and `QuizPlayer.withShownOrders` submits the arrangement already on screen), `matching` (`{pairs: [{id, rightId, left, right}]}` — the player view sends `{lefts, rights}` with the right column shuffled and nothing linking the two, the answer is `pairs: {pairId: rightId}`, graded proportionally with one right tile per pair), `cloze` (`{gaps: [{answers: []}]}` with `{{n}}` markers in the prompt — `playerView` exposes only `{gaps: n}`, the answer is `gaps: {n: text}`, graded proportionally per gap with `normalizeText`; `promptText` renders the markers as `___` in reviews, and the player hides the generic prompt heading because the sentence *is* the prompt).
- **Backend**: one Express 5 app (`server/app.ts`) exported as the single Vercel function `api-src/index.ts` (esbuild bundles it into the committed `api/index.mjs`). `server/app.ts` is now just the composition root (middleware, auth gate, MCP mount, router mounting, error handler); the handlers live in `server/routes/` by domain — `quizzes.ts`, `tokens.ts`, `classes.ts`, `progress.ts` (reviews + streak), `learning.ts` (verbs, courses, exam), `admin.ts` (feedback, users, audit, settings) — and shared `HttpError`/id helpers in `server/http.ts`. Adding a route means adding it to the matching `register*Routes(router)`; route order across modules is free because the paths are disjoint. `/api/*` and `/.well-known/*` are routed by `rewrites` in `vercel.json`; the app strips the `/api` prefix itself. The only redirect is the SPA fallback `/* → /index.html`, which applies only when no function or file matches. Routes: quizzes CRUD (`/api/quizzes`, `?difficulty=&sort=recent|popular`), `POST /api/quizzes/:id/grade` (grades and saves a `quiz_attempts` row), `GET /api/attempts`, `GET /api/irregular-verbs` (filters difficulty/popularity/pattern), `POST /api/quizzes/generate/irregular-verbs`, courses (`/api/courses`, `/:id`, `/:id/lessons/:lessonId`, `POST .../complete`, `POST /:id/exam`), `GET /api/health`. Data access: `server/quizRepo.ts`, `server/coursesRepo.ts`, `server/irregularVerbs.ts` (raw SQL via the `pg` pool from `getDatabase()`; create/replace run in a transaction; `PUT` replaces all questions/options, so their ids change). Class data is split into `server/classes/` (`classes.ts` — classes/join codes/members/students, `assignments.ts` — assignments + the facts/judge helpers + `myAssignments`/`classReport`, `results.ts` — `studentResults`, `allAttempts`, admin student search) with `server/classesRepo.ts` kept as a barrel so `import * as classes` call sites stay unchanged. Server code lives in `server/` and is type-checked by `tsconfig.server.json`.
- **Auth (Auth0)**: tenant `dev-4xxb1z18b3z4hc6s.us.auth0.com`, SPA app "Quiz SPA" and API "Quiz API" (audience `https://api.quiz.local`); configuration in `.env` (gitignored, see `.env.example`; the same vars are set on the Vercel project `quiz-vercel`, whose URL `https://quiz-vercel-rho.vercel.app` (plus `https://*.vercel.app` for previews) is in the app's callback/logout/origin lists next to localhost; env changes need a redeploy). **The whole API is private** (only `GET /api/health` is public): `server/auth.ts` `authenticate` resolves `Authorization: Bearer <credential>` where the credential is either an Auth0 JWT (`express-oauth2-jwt-bearer`, errors swallowed → anonymous) or a personal API token (`qz_…`, looked up by SHA-256 hash in `api_tokens`, revoked/expired ones rejected); `requireAuthenticated` then answers 401 with a `WWW-Authenticate: Bearer` challenge. The result is an `Identity {userId, permissions, via: 'jwt'|'token'}` (`identityOf`/`currentUserId`/`hasPermission`). Personal tokens (`server/apiTokens.ts`, `/api/tokens` — create/list/revoke, JWT-session only, max 20 active, shown once) act as their owner with a permission snapshot chosen at creation (`write:quizzes` only if the creator is admin); managed in Settings (`src/features/auth/ApiTokens.tsx`). Roles (Auth0 RBAC, `enforce_policies` + permissions in the access token): `admin` (existing tenant role holding `write:quizzes` for this API; Google account) and `student` (Discord account; users without a role are treated as students). The "Quiz: roles claim" Action (post-login, only for the Quiz SPA client) adds `https://quiz.local/roles` to the tokens for the UI; the server authorizes by permissions only (`requirePermission`). Needs `write:quizzes`: quiz create/update/delete and `?include=answers` (`quizzes.owner_id` is only recorded). Course exams can only be graded by the user who started them. Frontend: `src/features/auth/` — `AuthProvider` (inside the router; shows a sign-in/register page — `screen_hint: 'signup'` opens Auth0's sign-up form — to anonymous visitors, rendered in `PublicShell`, which always follows the OS color scheme instead of the saved theme setting; otherwise publishes the token getter used by the RTK Query `prepareHeaders` in `src/app/api.ts`), `useAuth`, `RequireRole`. Without `VITE_AUTH0_*` the app only shows a configuration notice. Lesson progress, attempts and course stats are keyed by `user_id`.
- **Errors, feedback and admin panel**: errors go to Sentry (optional: only when `VITE_SENTRY_DSN` / `SENTRY_DSN` are set). Frontend: `src/app/sentry.ts` (release = `__APP_VERSION__`, set in `vite.config.ts` from `VERCEL_GIT_COMMIT_SHA`; user = Auth0 `sub` only), `Sentry.ErrorBoundary` in `main.tsx` with `ErrorFallback` (reload + "report a problem"), RTK Query middleware `src/app/errorTracking.ts` reports 5xx/network failures only (4xx is normal flow). Server: `server/sentry.ts` + the Express error handler (structured JSON log, `requestId` from `x-nf-request-id`, response `{error, requestId, eventId}`; `X-Request-Id` header on every response). Feedback: `src/features/feedback/` (Redux `feedbackUi` slice opens `FeedbackModal`, mounted in `App.tsx`; entries in the user menu/drawer and Settings), `POST /api/feedback` stores type/message plus diagnostics (route, app version, UA, viewport, theme, Sentry event id, last failed request id) in `feedback`. Admin panel = tabs in Settings visible with the `admin` role (`Użytkownicy`, `Uwagi`, `Audyt`; components in `src/features/admin/`), backed by `/api/admin/*` which needs the Auth0 permission `manage:users` (only the admin role has it, never granted to personal tokens). User management goes through the Auth0 Management API with the dedicated M2M app "Quiz Management" (`server/auth0Management.ts`, env `AUTH0_MGMT_CLIENT_ID/SECRET`, secret stored as a Vercel secret for Production/Preview/Development and in `.env.local` locally; scopes: read:users, update:users, read:roles, read:role_members, create:role_members, delete:role_members). It only manages the roles `admin`/`teacher`/`student` (other tenant roles are untouched), refuses to remove your own admin role, the last admin's role, or to block yourself/the last admin, caches role membership for 15s and retries once on 429 (the tenant's Management API limit is low), and writes every change to `admin_audit_log`. Role changes take effect after the user logs in again. In local dev the API is served by `scripts/dev-server.mjs` (same bundled function as production), so error codes match the deployment.
- **Generated quizzes**: `server/irregularVerbs.ts` builds quizzes from the verb catalog and stores them as normal quizzes with `kind = 'generated'` and `source` (`irregular-verbs` or `course-exam`); they are hidden from `GET /api/quizzes` and never cleaned up (attempts keep a `quiz_title` snapshot and survive quiz deletion via `ON DELETE SET NULL`). Variants (`mixed`, `typing`, `choice`, `translation`) × difficulty × popularity filters; distractors include the naive regular form ("goed") and always come from the whole catalog. Translation questions accept every verb sharing the Polish meaning (robić = do/make).
- **Subjects**: quizzes are grouped by school subject — lookup table `subjects` (`math`…`other`, migration `20261019100000_quiz_subjects.sql`), `quizzes.subject_id` (nullable), fixed list `SUBJECTS`/`SUBJECT_LABELS` in `src/shared/quiz/types.ts`, `subject` field in `quizInput`/`data/quiz.schema.json`. `GET /api/quizzes?subject=<code>|none` and `quiz_list` filter by it; Home groups cards under subject headings (pure `src/shared/quiz/subjectGroups.ts`, tests in `tests/subjectGroups.test.ts`), the editor has a subject select. Generated quizzes have no subject.
- **Quiz play settings**: columns `quizzes.shuffle_questions` (NULL = follow the player's setting, true/false overrides it), `shuffle_options` and `sample_size` (NULL or 10/20/30 questions drawn from the whole pool on every play), edited in the "Ustawienia quizu" card of `QuizEditor`. Pure helpers in `src/shared/quiz/sampling.ts` (`tests/sampling.test.ts`); `QuizPlayer.prepareQuestions` samples/shuffles on the client and sends the shown `questionIds` with the grade request; the server grades exactly those (`resolveGradedIds`: must be `sample_size` distinct questions of the quiz, else 400; a missing list grades the whole pool). Generated quizzes use the defaults.
- **MCP server**: `POST /api/mcp` (`server/mcp/` — `index.ts` handler, `quizTools.ts`, `classTools.ts` (entry point; the 18 class/student/assignment tools live in `server/mcp/tools/{classes,students,assignments}.ts` with shared schemas and read/change guards in `tools/shared.ts`), `tools/admin.ts` (the `attempt_*` tools for admins, gated on `manage:users` so OAuth only), `context.ts` with the shared refusals/audit; `@modelcontextprotocol/sdk`) — stateless Streamable HTTP with JSON responses behind the normal authentication (personal token or Auth0 JWT). Tools are named `<object>_<action>` (`quiz_*`, `verbs_list`, `class_*`, `student_*`, `assignment_*`, `course_list`, `attempt_*`); destructive ones need `confirm: true`; **every change is written to `admin_audit_log` as `mcp.call`**. Quizzes: changes need `write:quizzes`. Classes: access rules in `server/classAccess.ts` (shared with the REST routes) — a teacher (`manage:classes`) reads/changes only own classes, an admin (`manage:users`, OAuth login only) can additionally *read* every class (`scope: all`), nobody changes a class they do not own. A personal token only has `manage:classes` when a teacher creates it with `classes: true` (Settings). Students are added by **Auth0 id**, picked with a type-ahead (`GET /api/classes/:id/student-candidates?q=`, `student_search`: ≥3 chars, ≤8 hits, e-mail masked by `maskEmail` because it is a directory lookup over `user_profiles`) (`POST /api/classes/:id/members`, `student_add`; the account must exist: Auth0 Management or a `user_profiles` row). Pure stats: `src/shared/quiz/studentAnalysis.ts`, `classAnalysis.ts`. Uses the *web-standard* transport on purpose: the Node one reads raw headers that the serverless adapter's request lacks (symptom: 415 "Content-Type must be application/json"). Docs: `docs/mcp.md`, `docs/mcp-clients.md` (registration per client, OAuth apps, revocation), `docs/mcp-grok.md` (Grok connects through Auth0 OAuth with the app "Quiz MCP (Grok)"; the tenant has `default_audience` = the API).
- **Class panel (UI)**: `/manage/classes` (`ClassPanel`, teacher or admin; user menu "Zarządzanie klasami") lists classes with owner, students, joining switch, code and expandable student lists (add by Auth0 id / remove via `features/classes/ClassParts`). Admins get `scope=all` and a read-only view (`podgląd`): `ClassDetail` hides every change control when `cls.ownerId !== user.sub`. `/results` shows a `StudentPicker` for teachers/admins (`?student=<classId>::<auth0 id>`, `StudentResultsView`, shared with `StudentResults`). `RequireRole` accepts a list of roles. Admins get a different picker on `/results` (`AdminStudentPicker`, `?user=<auth0 id>`; an old `?student=` link maps to the same user) showing **all** results of any app user (`AdminStudentResultsView` ← `GET /api/admin/students/:userId/results`, `manage:users`, JWT only): every attempt incl. random/review quizzes with answers, streak/goal, lessons, weak verbs, classes. Teachers stay limited to their class assignments (that is what students are told when joining).
- **Score colours and app settings**: every percent shown (results tables, student/admin views, class report, quiz result, home cards) uses `useScoreColors()` / `ScoreTag` / `ScoreProgress` (`src/features/results/`): red below `low`, orange below `high`, green from `high` (pure `src/shared/quiz/scoreBands.ts`, defaults 50/80). Thresholds are a global setting in table `app_settings` (`server/appSettingsRepo.ts`; `GET /api/settings/app` for everybody, `PUT /api/admin/settings/app` with `manage:users`, audited as `settings.update`), edited in Settings → Aplikacja (`AppSettingsAdmin`). Attempt lists share `AttemptsTable` (sortable columns, type filter, pagination 10/20/50/100, expandable answers, card rows on phones).
- **Learning module**: courses → lessons (8 verbs each, seeded by `20261017160200_learning_courses.sql` per difficulty level plus a "core verbs" course) → `lesson_verbs`. `lesson_progress` is per user; the final exam (`POST /courses/:id/exam`, 409 until all lessons are completed) is a generated quiz with `course_id`; grading it stores `quiz_attempts.course_id` and `passed` (percent ≥ `courses.pass_percent`, default 70) and returns `course` in the grade response.
- **Vercel config**: `vercel.json` builds with `npm run build && npm run build:api` into `dist` and routes `/.well-known/*` + `/api/*` to `api/index.mjs` via `rewrites`, everything else to the SPA. Locally `npm run dev:full` reproduces it on http://localhost:8888 (Vite proxied). Runbook: `docs/vercel.md`.
- **Database**: schema lives in SQL migrations in `db/migrations/`. Quiz tables: `quizzes` → `questions` → `options` (cascading), `quiz_attempts`. Verb catalog is normalized: `irregular_verbs` + lookups `cefr_levels`, `difficulty_levels`, `popularity_tiers`, `verb_patterns` (AAA/ABA/ABB/ABC, derived from forms) and child rows `verb_forms` (alternatives like learnt/learned, one row each) and `verb_meanings`. Difficulty is derived from pattern + popularity (rule in `...160100_verb_classification_and_examples.sql`). The old `planets` table is an unused template leftover. Apply them with `npm run db:migrate` (uses `DATABASE_URL`); **Vercel does not apply migrations on deploy**, so run them after any schema change. ## Dokumentacja (Obsidian vault)

- Vault Obsidiana znajduje się w `docs/` i jest jednocześnie dokumentacją repozytorium.
  Konfiguracja w `docs/.obsidian/` (pluginy core, szablony, grupy kolorów grafu).
- Indeks (MOC): `docs/00-Index/Index.md`; taksonomia tagów: `docs/00-Index/Tags.md`.
- Szablony: `docs/Templates/Note.md`, `docs/Templates/Doc.md`.
- Każda notatka ma frontmatter `tags:` (co najmniej jeden tag domeny i typu) oraz
  `created`/`updated`. Tagi zagnieżdżone z `/` (`#status/todo`).
- MCP: `mcp-obsidian` (stdio) wystawia `read_notes` i `search_notes`; konfiguracja w
  `.mcp.json` (Claude Code) i `.vscode/mcp.json` (VS Code / Copilot).
- OpenCode: wpis `obsidian` w `~/.config/opencode/opencode.jsonc` (wrapper
  `~/.local/bin/obsidian-mcp` z powodu niekompatybilności zod v4 w oryginalnym
  pakiecie).

## Gotchas

- The tsconfigs need TypeScript 6 (`~6.0.2`); some packages install an older TypeScript as a peer and `tsc -b` then breaks. Re-check `package.json` after adding dependencies.
- npm 11.21+ blocks dependency install scripts unless `package.json` has an `allowScripts` entry (the build log lists skipped packages as `npm warn install-scripts`). Both entries here are deliberate: `esbuild@0.28.2: true` (its postinstall validates/fetches the platform binary) and `browser-tabs-lock: false` (its postinstall only prints a banner). Approvals are pinned, so bumping esbuild re-triggers the warning — review with `npm install-scripts ls`, refresh with `npm install-scripts approve <pkg>`, drop stale pins with `prune`. Older npm (9.x local, 10.x CI) ignores the field.
- The build log prints `npm warn Unknown env config "cache-dir"`: nothing in this repo sets it (no `.npmrc` anywhere, not in the env files or the site's variables) — the build environment passes that legacy key. Harmless until npm 12, which turns it into an error; the fix belongs to the platform.
