# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"quiz" is an early-stage React 19 + TypeScript + Vite app (Ant Design, React Router, Redux Toolkit + RTK Query) deployed on Netlify, with a Netlify Functions backend backed by Netlify Database.

## Commands

- `npm run dev` — Vite dev server (frontend only; use `npx netlify dev` to run Vite plus functions on :8888)
- `npm run build` — `tsc -b && vite build` (output in `dist/`)
- `npm run lint` — Oxlint (config in `.oxlintrc.json`; not ESLint)
- `npm run preview` — serve the production build
- No test runner is configured.

## Architecture

- **Frontend**: `index.html` → `src/main.tsx` (Redux `Provider`) → `src/App.tsx` (antd v6 `ConfigProvider` + antd `App` + React Router). antd 6 supports React 19 natively, so no compatibility patch is needed. Routes: `/` (quiz list with difficulty filter/popularity sort + random irregular-verbs quiz generator), `/learn` (courses), `/learn/:courseId`, `/learn/:courseId/lessons/:lessonId`, `/verbs`, `/results`, `/quizzes/new`, `/quizzes/:id/edit`, `/quizzes/:id/play`, `/about`, `/settings`, 404 — pages in `src/pages/` under `src/components/AppLayout.tsx`; client routes rely on the SPA fallback at the end of `netlify.toml`. Quiz UI is in `src/features/quizzes/`: `QuizEditor` (antd Form + `Form.List`, with `OptionsEditor` adapting to question type), `QuizPlayer`, and `questionRenderers.tsx` (player input per question type).
- **State**: `src/app/store.ts` combines the RTK Query `api` (`src/app/api.ts`, base URL `/api`; Quiz tags invalidate the list/detail caches) and the `settings` slice (`themeMode` light/dark/system, `compact`, `showExplanations`, `shuffleQuestions`). Settings are persisted to localStorage key `quiz:settings` by a store subscriber and preloaded/validated in `src/app/persist.ts` (synced across tabs). To add a persisted option, extend the slice, `defaultSettings` and `loadSettings`. `system` theme is resolved by `useResolvedTheme`.
- **Quiz engine** (`src/shared/quiz/`, imported by both frontend and server): `engine.ts` holds the question-type registry (`questionTypes`: validate + grade per type — `single`, `multiple`, `truefalse`, `text`) and `gradeQuiz`; `schema.ts` has the zod input schemas (type-specific rules run through the registry); `types.ts` the API shapes. To add a question type: add it to `QUESTION_TYPES` and `questionTypes`, a renderer in `questionRenderers.tsx`, and a branch in `OptionsEditor`. Grading is server-side only; the player view of a quiz (`GET /api/quizzes/:id`) omits `isCorrect`, explanations and the options of `text` questions — `?include=answers` returns the editor view.
- **Backend**: one Express 5 app (`server/app.ts`) wrapped with `serverless-http` in the single function `netlify/functions/api.mts`. `netlify.toml` rewrites `/api/*` to `/.netlify/functions/api/:splat`; the app strips that prefix itself. Routes: quizzes CRUD (`/api/quizzes`, `?difficulty=&sort=recent|popular`), `POST /api/quizzes/:id/grade` (grades and saves a `quiz_attempts` row), `GET /api/attempts`, `GET /api/irregular-verbs` (filters difficulty/popularity/pattern), `POST /api/quizzes/generate/irregular-verbs`, courses (`/api/courses`, `/:id`, `/:id/lessons/:lessonId`, `POST .../complete`, `POST /:id/exam`), `GET /api/health`. Data access: `server/quizRepo.ts`, `server/coursesRepo.ts`, `server/irregularVerbs.ts` (raw SQL via the `pg` pool from `getDatabase()`; create/replace run in a transaction; `PUT` replaces all questions/options, so their ids change). Server code lives in `server/` (not under `netlify/functions/`, where every file would become a function) and is type-checked by `tsconfig.server.json`.
- **Auth (Auth0)**: tenant `dev-4xxb1z18b3z4hc6s.us.auth0.com`, SPA app "Quiz SPA" and API "Quiz API" (audience `https://api.quiz.local`); configuration in `.env` (gitignored, see `.env.example`; the same vars plus `SECRETS_SCAN_OMIT_KEYS` are set on the Netlify site `fabulous-dieffenbachia`, whose URL `https://fabulous-dieffenbachia.netlify.app` is in the app's callback/logout/origin lists next to localhost; env changes need a redeploy). **The whole API is private** (only `GET /api/health` is public): `server/auth.ts` `authenticate` resolves `Authorization: Bearer <credential>` where the credential is either an Auth0 JWT (`express-oauth2-jwt-bearer`, errors swallowed → anonymous) or a personal API token (`qz_…`, looked up by SHA-256 hash in `api_tokens`, revoked/expired ones rejected); `requireAuthenticated` then answers 401 with a `WWW-Authenticate: Bearer` challenge. The result is an `Identity {userId, permissions, via: 'jwt'|'token'}` (`identityOf`/`currentUserId`/`hasPermission`). Personal tokens (`server/apiTokens.ts`, `/api/tokens` — create/list/revoke, JWT-session only, max 20 active, shown once) act as their owner with a permission snapshot chosen at creation (`write:quizzes` only if the creator is admin); managed in Settings (`src/features/auth/ApiTokens.tsx`). Roles (Auth0 RBAC, `enforce_policies` + permissions in the access token): `admin` (existing tenant role holding `write:quizzes` for this API; Google account) and `student` (Discord account; users without a role are treated as students). The "Quiz: roles claim" Action (post-login, only for the Quiz SPA client) adds `https://quiz.local/roles` to the tokens for the UI; the server authorizes by permissions only (`requirePermission`). Needs `write:quizzes`: quiz create/update/delete and `?include=answers` (`quizzes.owner_id` is only recorded). Course exams can only be graded by the user who started them. Frontend: `src/features/auth/` — `AuthProvider` (inside the router; shows a sign-in page to anonymous visitors, otherwise publishes the token getter used by the RTK Query `prepareHeaders` in `src/app/api.ts`), `useAuth`, `RequireRole`. Without `VITE_AUTH0_*` the app only shows a configuration notice. Lesson progress, attempts and course stats are keyed by `user_id`.
- **Generated quizzes**: `server/irregularVerbs.ts` builds quizzes from the verb catalog and stores them as normal quizzes with `kind = 'generated'` and `source` (`irregular-verbs` or `course-exam`); they are hidden from `GET /api/quizzes` and never cleaned up (attempts keep a `quiz_title` snapshot and survive quiz deletion via `ON DELETE SET NULL`). Variants (`mixed`, `typing`, `choice`, `translation`) × difficulty × popularity filters; distractors include the naive regular form ("goed") and always come from the whole catalog. Translation questions accept every verb sharing the Polish meaning (robić = do/make).
- **Learning module**: courses → lessons (8 verbs each, seeded by `20261017160200_learning_courses.sql` per difficulty level plus a "core verbs" course) → `lesson_verbs`. `lesson_progress` is per user; the final exam (`POST /courses/:id/exam`, 409 until all lessons are completed) is a generated quiz with `course_id`; grading it stores `quiz_attempts.course_id` and `passed` (percent ≥ `courses.pass_percent`, default 70) and returns `course` in the grade response.
- **Netlify config**: `netlify.toml` builds with `npm run build` into `dist`. `[dev]` runs Vite (`npm run dev`, port 5173) behind `netlify dev` on http://localhost:8888, which also serves the functions, e.g. `curl localhost:8888/api/planets`.
- **Database**: schema lives in SQL migrations in `netlify/database/migrations/`. Quiz tables: `quizzes` → `questions` → `options` (cascading), `quiz_attempts`. Verb catalog is normalized: `irregular_verbs` + lookups `cefr_levels`, `difficulty_levels`, `popularity_tiers`, `verb_patterns` (AAA/ABA/ABB/ABC, derived from forms) and child rows `verb_forms` (alternatives like learnt/learned, one row each) and `verb_meanings`. Difficulty is derived from pattern + popularity (rule in `...160100_verb_classification_and_examples.sql`). The old `planets` table is an unused template leftover. Apply migrations locally with `npx netlify database migrations apply`; Netlify applies them on deploy, so never change schema via direct connections or edit applied migrations.
- `.agents/skills/netlify-*/` contains Netlify-provided reference skills (functions, database, deploy, config, etc.); consult the relevant `SKILL.md` before changing Netlify-specific code.
- `.netlify/` is local Netlify state (gitignored).

## Gotchas

- The tsconfigs need TypeScript 6 (`~6.0.2`); installing Netlify packages previously downgraded it to 4.9, which breaks `tsc -b`. Re-check `package.json` after adding dependencies.
